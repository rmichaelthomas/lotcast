# Draw Page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the receipt-checker page at `/` with a front page where anyone can make an I Ching or tarot draw, watch it arrive, see it checked, and save its receipt.

**Architecture:** The page stays static files in `verify-web/public/`, served by the existing Cloudflare Worker before any code runs. Guion, running in the browser VM, does everything that needs trust: sealing the question, building the request, checking the service's signed promise, and verifying the receipt. It runs the same code the command line uses, moved into `lotcast-core`. A small, DOM-free JavaScript module does what the VM can't: random bytes, `fetch`, polling, storage and downloads. A thin page script wires that module to the markup from the approved mockup.

**Tech Stack:** Guion 0.9 (native tests with `guion test`, the browser VM via the vendored `loader.mjs`), plain ES modules, `node --test`, AllHereHTML instruments (authored to their registry contracts), Geist and Geist Mono served from the page, and Playwright for the live browser run.

**Spec:** `docs/superpowers/specs/2026-11-25-draw-page-design.md`. The approved look is the "Version 2" row of https://claude.ai/artifact/XZJAnxkfjVk1UwfwKMSRsH.

## Global Constraints

- The question never leaves the device. Only `commitment` = `question_commit(question, salt)` is sent. The request body never has a `question` key.
- Say "Verified" only for verdict `verified`. `verified-pending-live` reads "Not fully checked yet", and `verified-unanchored` reads "Partly verified". Use the wording from the existing `HEADLINES` in `verify-web/public/index.html`.
- Before showing any draw, the page runs the same binding check the command line does (`view_problem` and `binding_problem`). On a binding problem it shows "Do not trust this draw: <problem>" and shows no outcome.
- Default sources are the command line's `live_sources()`: `["curby-rng", "drand-quicknet", "nist-beacon-2"]`.
- No meanings anywhere. Show only names, numbers, lines, and upright or reversed.
- No badge, seal or decoration may cover text or any part of the draw. The seal is a sibling in normal flow, never `position: absolute`.
- No request to any origin other than the page's own. Fonts are served from `public/fonts/`.
- Colors: `#12102a` ground, `#17153a` and `#1c1940` panels, `#3a3566` rules, `#b9b4d9` muted, `#f2ead9` bone, `#16142e` ink on bone, `#d9b36c` brass, `#c8361f` seal (seal and Draw button only). Type: Geist, Geist Mono.
- All motion stops under `prefers-reduced-motion: reduce`.
- Every decorated piece carries `data-ahi="<AllHere id>"` and follows that id's registry `element` and `fallback`. AllHereHTML is never edited from this repo.
- The existing check-a-receipt behavior and its tests keep working.

## Review Focus

1. **A second draw within a minute.** The service rate-limits `POST /v1/draws` (`rate_hit(..., 60)`) and answers 429. The visitor should see "Lotcast allows one draw a minute from each connection. Try again in a minute." and their choices should stay in the form. Tested in Task 3.
2. **The tab is closed or reloaded mid-wait.** The pending draw (id, request, entry hash, salt and question) is in `localStorage` under `lotcast:pending`. On load the page resumes polling instead of showing the empty form. Tested in Task 3.
3. **The time-stamps failed** (`status: "anchor-failed"`). The page says the draw couldn't be time-stamped, nothing was drawn, and they can draw again. It clears the pending record and never shows an outcome. Tested in Task 3.
4. **A long wait or a dropped connection while polling.** A failed poll retries with backoff, up to 2 s → 10 s, and doesn't give up. After 10 minutes the page says the draw is still waiting and keeps the pending record so a reload resumes it. Tested in Task 3.
5. **A huge or odd question** (emoji, 5,000 characters, only spaces). It is sealed as typed. A question that is only spaces counts as "no question". Tested in Task 2.

### Task 3: The draw flow (DOM-free JavaScript)

**Files:**
- Create: `verify-web/public/draw-flow.mjs`
- Test: `verify-web/draw-flow.test.mjs` (uses the real VM and `verify.gub`, and a fake `fetch` that replays scripted responses)

**Interfaces:**
- Consumes: Task 2's entry points, called through `deps.vm(entry, args) -> string`.
- Produces:
  - `startDraw(choice, deps) -> Promise<Pending | Failure>`. `choice = { tradition, method, options: {..text}, question }`. `deps = { vm, fetch, random(n) -> Uint8Array, store, operatorKey }`. It uses a 16-byte nonce and a 32-byte salt. It POSTs `plan.body` to `/v1/draws` with `content-type: application/json`, runs `check_view` on the reply, and saves `Pending = { id, index, tradition, method, request_json, entry_hash, question, salt_hex, startedAt }` to `store` under `lotcast:pending`.
  - `pollDraw(pending, deps, onProgress) -> Promise<Done | Failure>`, with `deps` adding `sleep(ms)` and `now()`. It GETs `/v1/draws/{id}` every `poll_after_ms`, retries failed polls with backoff from 2 s up to 10 s, and runs `check_view` on every view. When the view is `complete`, it runs `verify_draw` and returns `Done = { receipt, outcome, verdict }`, then removes `lotcast:pending`.
  - `progress(view) -> { logged: bool, stamped: bool, sourcesIn: number, sourcesTotal: 3, done: bool }`. `logged` is false while `waiting_on` has a `"log"` entry. `stamped` is false while it has an `"anchor"` entry. `sourcesIn = 3 −` the number of `waiting_on` entries whose `source` is one of the three live source ids.
  - `Failure = { kind: 'rate-limited' | 'refused' | 'unreachable' | 'untrusted' | 'anchor-failed' | 'still-waiting', message }`, with these exact messages:
    - `rate-limited`: "Lotcast allows one draw a minute from each connection. Try again in a minute."
    - `refused`: "Lotcast turned this request down: <the service's error.message>"
    - `unreachable`: "Couldn't reach Lotcast. Check your connection and try again."
    - `untrusted`: "Do not trust this draw: <problem>"
    - `anchor-failed`: "This draw couldn't be time-stamped, so nothing was drawn. You can draw again."
    - `still-waiting`: "Your draw is still waiting for random numbers. Leave this page open, or come back later on this device."
  - `resumePending(store) -> Pending | null`

- [ ] **Step 1: Write the failing tests:**
  - `startDraw never sends the question`: capture the POST body, then assert it has no `question` and doesn't contain the question text.
  - `a 429 is rate-limited and leaves no pending record`
  - `a reply whose promise doesn't verify is untrusted`: use the fixture view with `promise` changed.
  - `pending is saved before polling and resumePending returns it`
  - `polling reports progress then verifies`: script pending with `waiting_on` `[log]`, then `[anchor]`, then `[curby-rng, nist-beacon-2]`, then the complete fixture view. Assert the `progress` sequence and that `verdict.verdict === 'verified'`.
  - `anchor-failed clears pending and shows no outcome`
  - `a dropped poll retries`: `fetch` throws once, then succeeds.
  - `ten minutes of waiting is still-waiting and keeps pending`: fake `now`.
- [ ] **Step 2: Run them to see them fail.** `cd verify-web && node --test draw-flow.test.mjs`. Expected: FAIL, module not found.
