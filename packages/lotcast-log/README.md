# lotcast-log

The append-only log and the time anchoring behind Lotcast receipts, in Guion.

- `merkle.gu`: RFC 6962 leaf and node hashing (SHA-256), tree roots, inclusion and consistency proofs, and the RFC 9162 verification algorithms.
- `note.gu`: C2SP signed notes (Ed25519 signature lines with a four-byte key hash) and the tlog checkpoint text (`origin`, size, base64 root).
- `tiles.gu`, `log.gu`: the C2SP tlog-tiles layout (height-8 hash tiles, entry bundles of uint16-prefixed entries) in a directory. `log_open` re-derives every tile from the stored entries and compares them with the signed checkpoint, so a corrupt or truncated log fails closed. `log_append_many` keeps a repeated entry at its first index, writes the changed tiles and bundles, and writes the signed checkpoint last.
- `anchor.gu`, `tsa_pins.gu`: RFC 3161 anchoring. `tsa_stamp` posts a request to a pinned authority; `tsa_check` accepts a token only when a certificate the token carries is issued by the pinned issuer and the token covers the digest; `anchor_g` is `max(genTime + accuracy) + 1 s`; `choose_tsas` falls back to FreeTSA after ten minutes of one authority failing. The stamped digest is SHA-512 of the checkpoint's signed text, so witness cosignatures added later do not change it.

Pins are the certificates that issued each authority's signing certificate (`src/tsa_pins.gu`, generated by `scripts/gen_tsa_pins.gu` from `fixtures/tsa`, fetched by `scripts/fetch_tsa_fixtures.sh`). Signing certificates rotate; an issuer rotation needs a new pin and a new version.

```
guion test                # offline: vectors from reference/python, real TSA tokens
guion run --allow-http-host timestamp.digicert.com --allow-http-host timestamp.sectigo.com tests_live.gu
```

A program using the log needs `[approved-capabilities.lotcast-log]` with `files = ["read", "write"]` and the three TSA hosts under `network`.
